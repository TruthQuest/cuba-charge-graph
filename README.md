# cuba-prisoners-ontology

A formal ontology and reproducible analysis pipeline over the public registry of 1,258 Cuban political prisoners maintained by [Prisoners Defenders](https://www.prisonersdefenders.org/). Produces statistical evidence that the Cuban state operates two entirely disjoint prosecutorial charging regimes for political cases.

The primary finding, tested under a permutation null model (n=5,000, p<0.001), is that low-severity charges (Contempt, Public Disorder, Assault, Resistance) cluster into a "street-protest bundle" applied to demonstrators, while high-severity charges (Sedition, Sabotage, Enemy Propaganda) are applied as standalone charges to individuals the state characterizes as regime threats. The two clusters do not overlap. The pattern is stable across the five-year observation window and across every Cuban province.

Full report and interpretation: [`two_regimes.html`](./two_regimes.html) (also viewable at [project site]).

Formal submissions to human rights bodies drawing on this analysis are in [`submissions/`](./submissions/).

---

## Why this exists

Prisoners Defenders publishes an authoritative registry of Cuban political prisoners. Human rights organizations have documented individual cases and qualitative patterns for years. What has not previously existed is a machine-readable, statistically validated, reproducibly analyzable record of what the state's charging behavior looks like at the corpus level.

This repository is an attempt to build one. The intended users are:

- Human rights researchers preparing submissions to the UN Working Group on Arbitrary Detention, the Inter-American Commission, treaty bodies, and the Universal Periodic Review
- Journalists working on Cuba and the Caribbean
- Legal scholars working on selective prosecution and comparative criminal procedure
- Ontologists and semantic web researchers interested in human rights as a domain

Everything here is derivative of Prisoners Defenders' underlying documentation. Any use of this repository should acknowledge them as the source.

## Method in one paragraph

Records are scraped from `lista.prisonersdefenders.org` into JSONL, encoded into RDF as instances of a Basic Formal Ontology (BFO)-aligned T-Box, and validated against SHACL shapes that require provenance on every claim. Charge instances are linked to a SKOS-controlled vocabulary drawn from the 1987 and 2022 Cuban Penal Codes. The analysis layer computes charge-pair co-occurrence and compares against a null distribution generated by 5,000 iterations of random charge assignment preserving per-defendant charge count and per-charge marginal frequency. Every quantitative claim in the accompanying reports is traceable to a specific query against the merged graph.

The pipeline is deterministic. The same input produces the same output.

## Quick start

Requires Python 3.11 or later.

```bash
git clone https://github.com/[your-username]/cuba-prisoners-ontology.git
cd cuba-prisoners-ontology
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
playwright install chromium
```

To run the full pipeline against fresh data:

```bash
python scripts/01_scrape_prisoners.py           # ~30 min, respects robots.txt
python scripts/03_build_abox.py \
    --input data/prisoners.jsonl \
    --output ontology/cuban_prisoners_abox.ttl
python scripts/04_run_pipeline.py               # SHACL validation + wave inference
python scripts/05_analyze.py                    # ~1 min, writes CSVs to results/
```

To reproduce the reported results against the version-locked data snapshot bundled in this repo:

```bash
python scripts/04_run_pipeline.py
python scripts/05_analyze.py
```

The `results/` directory will be overwritten with fresh output. Compare against `results/reference/` to verify reproducibility.

## Key statistics from the current corpus

- **1,258** documented individuals
- **2,264** charges filed
- **158** detention facilities named
- **44,725** RDF triples in the merged graph before inference; **46,876** after wave inference
- **267** arrests on 11 July 2021 alone; **~500** in the following week
- **~14%** of prisoners held outside their home province
- **6 of 6** charge pairs within the street-protest bundle exceed the 99.9th percentile of the null distribution
- **2 of 2** charge pairs testing Sedition-with-street-bundle co-occurrence fall below the 5th percentile of the null distribution

## What the ontology does that a spreadsheet cannot

Modelling the corpus as a formal ontology is not a design choice for its own sake. Three things become possible that a flat table does not support:

**1. Separating the state's terminology from analytical assessment.** The SKOS vocabulary distinguishes `skos:prefLabel` (the state's charge name) from `skos:editorialNote` (analytical commentary tying the charge to international human rights standards). This matters for legal use: quoting the state's language accurately is required for admissibility; conflating it with analysis is not.

**2. Provenance on every claim.** Every fact in the graph carries a `prov:wasDerivedFrom` link to its source, and SHACL rejects any assertion of abuse or state practice that lacks such provenance. This is what makes the graph usable as evidence rather than as advocacy.

**3. Recovering unstated categories.** The two-regime finding was not visible in the state's own classifications because the state does not publish the distinction. It becomes visible only when charge co-occurrence is analyzed at the corpus level in a formalism that permits statistical querying. This is what a formal ontology, specifically, provides.

## Ethical framework

Every named individual is real. The Prisoners Defenders registry publishes names with the consent framework of the affected persons or their families. This repository re-processes their public data and adds analytical structure. It does not add PII, does not enrich records against secondary sources, and does not attempt re-identification of any individual not already publicly named.

The `policy/` directory contains a formal ethics overlay using the W3C Data Privacy Vocabulary (DPV) and Open Digital Rights Language (ODRL) declaring:

- Political opinion data as GDPR Article 9 special-category data
- Legal basis: legitimate interest for grave human rights documentation
- Prohibition on aggregation to derive further PII
- Prohibition on use as training data for ML systems targeting individuals
- Prohibition on commercial re-use

Every person in the current A-Box carries a conservative `policy:HighRisk` classification by default, requiring manual curation to downgrade. Records classified as HighRisk are excluded from access tiers below `policy:ResearchTier`.

If you are affiliated with a named individual and want your record reviewed, contact Prisoners Defenders directly. This project defers to the source on any curation of the underlying registry.

## Reproducibility statement

Every quantitative claim in the reports produced by this pipeline can be reproduced from the raw scraped data by running the four Python scripts in order. The pipeline is version-controlled. The dependencies are pinned in `requirements.txt`. The permutation test uses a fixed random seed (42) for reproducibility. Statistical results are stable across independent runs.

Where results depend on the specific state of the Prisoners Defenders registry at the time of scraping, the timestamp of the scrape is recorded in the ontology as `:scrapedAt` on every record. To reproduce the exact statistics reported in the current documents, use the bundled snapshot in `data/prisoners.jsonl` rather than re-scraping.

## Contributing

The analysis is designed to be extended, not merely reproduced. Areas where contributions are welcome:

- **Verification of individual records** against secondary sources (court filings, family testimony, prior HRW/Amnesty reporting)
- **Curation of fallback charge-type entries** into the SKOS vocabulary (approximately 65 charges are currently auto-generated and lack manual annotation against Cuban Penal Code articles)
- **Extension of the perpetrator scraper output** (`02_scrape_perpetrators.py`) into the ontology as a linked `:Perpetrator` class with `:allegedlyResponsibleFor` relations to specific arrests and facilities
- **Additional analyses**: co-defendant network analysis, sentence-length prediction, appeals outcome tracking
- **Translations** of the reports into Spanish

Open an issue before undertaking large changes. Coordinate with Prisoners Defenders on any change that touches the underlying case data.
